# PRD: Audio/Video Transcription via Local Whisper

**Дата**: 2026-05-29
**Статус**: Draft

## Цель

После загрузки mp3/mp4 файла во встречу — автоматически запустить локальную транскрибацию через Whisper (модель `base`) и сохранить текст в БД. Пользователь видит статус транскрибации рядом с файлом без перезагрузки страницы.

## Пользовательские сценарии

- Пользователь загружает mp3/mp4 файл во встречу → файл появляется в списке со статусом `PENDING`
- Система запускает Whisper в фоне → статус меняется на `IN_PROGRESS`
- Транскрибация завершается → статус меняется на `DONE`, текст транскрипции доступен
- Транскрибация падает с ошибкой → статус `FAILED`, пользователь видит индикацию ошибки
- Пользователь открывает встречу с уже транскрибированным файлом → сразу видит текст транскрипции

## В скоупе

- Автоматический запуск транскрибации после успешной загрузки mp3 или mp4 файла
- Локальный Whisper, модель `base` (лёгкая, низкое потребление ресурсов)
- Статусы транскрибации: `PENDING` → `IN_PROGRESS` → `DONE` / `FAILED`
- Хранение текста транскрипции в БД (поле `transcript` в `MeetingFile`)
- Polling на фронтенде для обновления статуса (без WebSocket)
- Показ статуса рядом с файлом в списке файлов встречи
- Показ текста транскрипции при статусе `DONE`
- Транскрибация только для mp3 и mp4 (mimeType: `audio/mpeg`, `video/mp4`)

## Не в скоупе

- Другие форматы файлов (wav, ogg, webm и т.д.)
- Выбор модели Whisper пользователем
- Ручной повторный запуск транскрибации при `FAILED`
- Редактирование текста транскрипции
- WebSocket / SSE для real-time обновлений
- Поддержка нескольких языков — Whisper определяет язык автоматически
- Облачный Whisper API (OpenAI)

## Технические ограничения

- Whisper запускается через `nodejs-whisper` или `child_process` → `whisper` CLI, оба варианта требуют Python + Whisper на машине
- Транскрибация блокирующая по CPU — запускается через NestJS Bull Queue (или `setImmediate`/worker) чтобы не блокировать event loop
- Модель `base` скачивается при первом запуске (~74 MB)
- Поле `filePath` в `MeetingFile` уже содержит абсолютный путь к файлу — его передаём в Whisper
- `MeetingFile` в Prisma нужно расширить: добавить `transcriptionStatus`, `transcript`, `transcriptionError`
- Polling интервал на фронте: 3 секунды пока статус не `DONE` или `FAILED`

## Критерии готовности

- [ ] Prisma схема: `MeetingFile` содержит `transcriptionStatus` (enum: `PENDING`, `IN_PROGRESS`, `DONE`, `FAILED`, `SKIPPED`), `transcript String?`, `transcriptionError String?`
- [ ] После загрузки mp3/mp4 файла статус устанавливается в `PENDING` и запускается фоновая задача транскрибации
- [ ] После загрузки файлов не-аудио/видео форматов статус `SKIPPED` (транскрибация не запускается)
- [ ] `GET /meetings/:id/files` возвращает `transcriptionStatus` и `transcript` для каждого файла
- [ ] Фронтенд показывает статус транскрибации рядом с каждым файлом: иконка/лейбл `PENDING`, `IN_PROGRESS`, `DONE`, `FAILED`
- [ ] Фронтенд делает polling каждые 3 сек пока хотя бы один файл в `PENDING` или `IN_PROGRESS`
- [ ] При статусе `DONE` фронтенд показывает текст транскрипции (раскрывающийся блок)
- [ ] При статусе `FAILED` фронтенд показывает сообщение об ошибке
- [ ] Загрузка файла не замедляется из-за транскрибации (задача запускается асинхронно после ответа API)
- [ ] e2e-тест: загрузка mp3 → статус `PENDING` в ответе upload endpoint
