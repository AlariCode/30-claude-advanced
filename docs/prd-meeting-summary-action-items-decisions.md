# PRD: Выжимка встречи через Claude Agent SDK (summary, action items, решения)

**Дата**: 2026-06-03
**Статус**: Draft

## Цель

После транскрибации встречи пользователь хочет получить автоматическую выжимку: краткое summary, список action items с ответственными и список принятых решений — чтобы не перечитывать весь транскрипт. Выжимка генерируется через Claude Agent SDK, сохраняется в БД и отображается на странице встречи.

## Пользовательские сценарии

- Пользователь открывает встречу с транскрибированными файлами и нажимает «Сгенерировать выжимку» -> запускается обработка, статус показывается на странице
- Пользователь ждёт завершения обработки -> на странице появляются три блока: summary, action items (с ответственными), принятые решения
- Пользователь видит action item -> рядом указан ответственный, если он упоминался во встрече (иначе — без ответственного)
- Пользователь нажимает «Перегенерировать выжимку» -> старая выжимка перезаписывается новой
- Пользователь, у которого транскрипция ещё не завершена -> кнопка генерации недоступна с пояснением

## В скоупе

- Выжимка генерируется **на уровне всей встречи**: транскрипты всех файлов встречи со статусом `DONE` объединяются в один контекст
- Генерация запускается **вручную** кнопкой на странице встречи (доступна только владельцу встречи)
- Через `ClaudeAgentService` (Claude Agent SDK) на основе объединённого транскрипта формируются:
  - **Summary** — краткое текстовое резюме встречи
  - **Action items** — список задач; для каждой: текст задачи и ответственный (если назван во встрече, иначе пусто)
  - **Принятые решения** — отдельный список решений
- Хранение результата в БД: новая модель/поля, связанные с `Meeting` (summary, action items, решения, статус генерации, текст ошибки, временные метки)
- Статус генерации выжимки: `PENDING` / `IN_PROGRESS` / `DONE` / `FAILED`
- Асинхронная обработка (не блокирует HTTP-ответ), по аналогии с текущей транскрипцией
- Поллинг статуса на фронтенде (как уже сделано для транскрипции) и отображение трёх блоков после завершения
- Возможность **перегенерировать** выжимку: повторный запуск перезаписывает предыдущий результат
- Обработка ошибок: при сбое — статус `FAILED` и понятное сообщение на странице

## Не в скоупе

- Выжимка на уровне отдельного файла
- Автоматический запуск генерации сразу после завершения транскрипции
- Редактирование summary / action items / решений пользователем вручную
- Назначение ответственных на реальных пользователей системы (только текстом из транскрипта)
- Экспорт выжимки (PDF, e-mail, интеграции с задачами/календарём)
- Версионирование/история предыдущих выжимок (перегенерация перезаписывает)
- Мультиязычная нормализация — выжимка формируется на языке транскрипта

## Технические ограничения

- Генерация возможна только если у встречи есть хотя бы один файл с `transcriptionStatus = DONE` и непустым `transcript`
- `ClaudeAgentService.ask()` принимает строку и возвращает строку — структурированный результат (summary/action items/решения) нужно получить и распарсить в надёжный формат (например, JSON в ответе модели) с валидацией
- Используется модель `claude-haiku-4-5-20251001`, `maxTurns: 1` — выжимка должна укладываться в один проход без инструментов
- Длинные транскрипты нескольких файлов могут превысить контекстное окно — нужно учесть ограничение объёма входа
- Зависимость от внешнего API (Anthropic proxy): сетевые ошибки/таймауты должны переводить статус в `FAILED`, а не подвешивать процесс
- Изменение Prisma-схемы должно следовать `.claude/rules/prisma.md`: UUID id, `createdAt`/`updatedAt`, enum в UPPER_CASE, `@relation` с явным именем, `@@index` на foreign keys

## Критерии готовности

- [ ] В Prisma-схеме есть хранилище выжимки, связанное с `Meeting`: summary, action items (текст + ответственный), решения, статус генерации, текст ошибки, `createdAt`/`updatedAt`
- [ ] Эндпоинт запуска генерации выжимки для встречи доступен только владельцу и защищён `JwtGuard`
- [ ] Запуск генерации, когда нет ни одного файла со статусом `DONE`, возвращает понятную ошибку и не создаёт пустую выжимку
- [ ] Транскрипты всех `DONE`-файлов встречи объединяются и передаются в `ClaudeAgentService`
- [ ] Ответ Claude распарсивается в три структуры: summary (текст), action items (массив: задача + ответственный), решения (массив); при невалидном ответе статус становится `FAILED`
- [ ] Статус генерации проходит цикл `PENDING -> IN_PROGRESS -> DONE`, а при ошибке -> `FAILED` с сообщением
- [ ] При сетевой ошибке/таймауте Claude API процесс не виснет, статус становится `FAILED`
- [ ] Повторный запуск генерации перезаписывает предыдущую выжимку
- [ ] На странице встречи есть кнопка «Сгенерировать выжимку» (и «Перегенерировать» при наличии результата), доступная только владельцу
- [ ] Фронтенд поллит статус и после `DONE` отображает три блока: summary, action items (с ответственными), принятые решения
- [ ] Состояния `IN_PROGRESS` и `FAILED` визуально отражены на странице встречи
- [ ] Все методы сервисов имеют явные типы параметров и `Promise<T>`, без `console.log` (Logger), в соответствии с CLAUDE.md
