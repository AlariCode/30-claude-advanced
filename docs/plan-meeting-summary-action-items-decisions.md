# Plan: Выжимка встречи через Claude Agent SDK (summary, action items, решения)

**PRD:** @docs/prd-meeting-summary-action-items-decisions.md
**Дата:** 2026-06-03

## Фазы реализации

### Фаза 1: Хранилище выжимки в БД (Tracer Bullet)

**Цель:** Появляется место для хранения выжимки встречи и статуса генерации — основа, на которую опираются все остальные фазы.
**Затрагивает:** database
**Задачи:**

- [ ] Добавить enum `SummaryStatus` (`PENDING` / `IN_PROGRESS` / `DONE` / `FAILED`) в Prisma-схему (UPPER_CASE)
- [ ] Добавить модель выжимки, связанную с `Meeting` через `@relation` с явным именем: поля `summary`, `actionItems`, `decisions`, `status`, `error`, `id` (UUID), `createdAt`, `updatedAt`, `@@index` на `meetingId`
- [ ] Создать и применить миграцию Prisma, обновить сгенерированный клиент
- [ ] Обновить `apps/api/CLAUDE.md` при изменении доменной модели

**Когда готова:** Миграция применяется, в БД есть таблица выжимки, связанная с встречей; покрывает критерий хранения из PRD.

### Фаза 2: Backend — генерация выжимки через Claude Agent SDK

**Цель:** По запросу встреча получает summary, action items с ответственными и список решений, сохранённые в БД.
**Затрагивает:** backend
**Задачи:**

- [ ] Сервис генерации: собрать транскрипты всех файлов встречи со статусом `DONE`, объединить в один контекст; если таких нет — вернуть понятную ошибку без создания пустой выжимки
- [ ] Сформировать промпт и вызвать `ClaudeAgentService.ask()`, распарсить JSON-ответ в три структуры (summary, action items с ответственным, decisions) с валидацией; при невалидном ответе / сетевой ошибке / таймауте — статус `FAILED` с сообщением
- [ ] Реализовать цикл статуса `PENDING -> IN_PROGRESS -> DONE`, асинхронный запуск (non-blocking), перезапись результата при повторной генерации
- [ ] Эндпоинт запуска генерации для встречи: защита `JwtGuard`, доступ только владельцу; эндпоинт чтения выжимки со статусом
- [ ] Тесты сервиса: успешная генерация, отсутствие `DONE`-файлов, невалидный ответ Claude, ошибка API, перегенерация; явные типы и `Promise<T>`, Logger вместо console.log

**Когда готова:** POST-запрос владельца запускает генерацию, результат с тремя структурами сохраняется в БД, статусы и ошибки корректны, тесты зелёные.

### Фаза 3: Frontend — отображение и управление выжимкой

**Цель:** Пользователь запускает генерацию со страницы встречи и видит summary, action items и решения после обработки.
**Затрагивает:** frontend
**Задачи:**

- [ ] Кнопка «Сгенерировать выжимку» на странице встречи (только владелец); недоступна с пояснением, если нет завершённой транскрипции; «Перегенерировать» при наличии результата
- [ ] Поллинг статуса генерации (по аналогии с транскрипцией), отражение состояний `IN_PROGRESS` и `FAILED` на странице
- [ ] Три блока после `DONE`: summary, action items (с ответственными), принятые решения
- [ ] Обновить типы фронтенда под структуру выжимки и статус
- [ ] Тесты компонента: отображение трёх блоков, доступность кнопки только владельцу, состояния загрузки/ошибки

**Когда готова:** Владелец со страницы встречи запускает и перегенерирует выжимку, видит три блока и состояния процесса; тесты зелёные.
